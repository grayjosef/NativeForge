## What must happen before live collection

1. `deploy_backend_process` — no long-running backend process exists; the API is started only by smoke scripts and no systemd unit serves it
2. `choose_worker_topology` — in-process (FastAPI lifespan) or external worker; main.py has no lifespan hook today
3. `select_broker_if_external` — only if the topology is external; an in-process or systemd-timer worker needs no broker and no dependency
4. `add_periodic_trigger` — a systemd .timer checked into the repo is detected by Gate 98E
5. `configure_production_object_store` — Gate 97's seam, deployed and round-tripped; a check with nowhere to put its bytes produces a number nobody can verify

## A dry-run worker is not monitoring

It is the shape a worker would have, exercised against jobs that cannot run. Processing a job here means reading it, checking it is a kind this worker may touch, and recording an outcome — everything a worker does *around* the work. The work itself is absent, and after this gate it is still absent.

The remaining components are `background_worker`, `periodic_trigger`, `scheduler_runtime`, and the production worker decision remains open.
