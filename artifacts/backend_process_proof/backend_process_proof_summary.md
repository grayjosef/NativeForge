## Why persistent_backend_live is false here

A running process is a property of one machine at one moment, not of this repository. Committed artifacts are compared against a fresh generation by test, so a pid or an observation timestamp in this file would fail that comparison on any other machine — and on this one, minutes later.

So the flag above means exactly one thing: **the committed contract carries no process proof.** A real proof was captured during the run and appears in the gate report. Both are true; they answer different questions.

## The lifespan hook

Attach point: `nativeforge.main:lifespan`. It fires on startup and shutdown and starts nothing.

| Fact | Value |
| --- | --- |
| `lifespan_hook_available` | true |
| `scheduler_attached` | false |
| `collectors_started` | false |
| `urls_fetched` | false |
| `source_monitoring_live` | false |

Having somewhere for a scheduler to attach is a prerequisite for attaching one. It is not attaching one. Before the hook existed, "no scheduler runs at startup" was true because startup did not exist; it is now true because startup ran and deliberately started nothing, which is a claim a test can check.

## What must be true before anything attaches

- `persistent_backend_live` — gate 101B/102B - a proven long-running process, not a smoke script
- `background_worker_available` — gate 98E - a worker module or console entry point; there is none
- `periodic_trigger_configured` — gate 98E - a timer or cron entry checked into the repo
- `production_raw_payload_store_available` — gate 96/97 - somewhere durable for a check's bytes to land
